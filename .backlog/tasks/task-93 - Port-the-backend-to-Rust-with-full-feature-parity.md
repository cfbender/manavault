## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace the Elixir/Phoenix backend with a Rust backend (rust/crates/manavault-server) that serves the same owner and public GraphQL schemas, routes, sessions, and Oban-compatible jobs over the same SQLite database, using the shared lotus crate for Magic domain code, Scryfall parsing/sync, and decklist sources. Branch rust-backend. Follows TASK-92.

Migrations on boot: rust/migrations/*.sql (one per Ecto migration, generated by mise run rust:migrations) are embedded and applied by db::migrate::run at startup with Ecto-compatible schema_migrations rows; seven Elixir data steps ported; pre-migration backup kept. Tested with a v1.0.0 database fixture with data (40 migrations applied, data intact), no-op on a migrated DB, unknown newer versions ignored like Ecto. README/self-hosting no longer require upgrading through an Elixir release.

Elixir removed: lib/, test/, config/, mix files, gettext, priv/repo deleted. rust/migrations/*.sql are the schema source (mise run rust:new-migration, rust:schema writes rust/schema.sql, rust:sqlx-prepare regenerates .sqlx); CI has separate Frontend and Rust jobs; versions come from Cargo.toml/package.json; the parity harness runs the Elixir reference from a git worktree of ELIXIR_REF (default b2b70d5). Request logging: web::request_id logs method/path and status/duration in a request{request_id} span, sets/propagates x-request-id (20..=200 bytes kept), skips static files, scanner bundles, and Scryfall assets, and feeds the server-log LogHub. Vendor prices load in keyset pages after the listener starts; reads fall back to Scryfall prices until then.
